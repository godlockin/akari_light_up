# 美术馆亮灯挑战 (Akari/Light Up) 设计文档

> 创建日期: 2026-02-12

## 一、项目概述

构建一个可部署到 Cloudflare Pages 的前端应用，让用户在线玩美术馆亮灯挑战游戏。

## 二、游戏规则

### 核心规则

| 规则 | 说明 |
|-----|------|
| **光线方向** | 灯泡沿横纵四个方向照射，不斜射 |
| **光线阻挡** | 黑格（墙壁）阻挡光线，无法穿透 |
| **黑格类型** | ①带数字：约束上下左右灯数量 ②无数字：纯阻挡光线 |
| **数字约束** | 黑格数字约束其上下左右4格的灯数量，对角不受限 |
| **灯不互照** | 每个灯不能被其他灯照亮 |
| **胜利条件** | 所有白色格子都被灯泡或光线覆盖 |

### 数字约束示例

```
  .   .   .
    ╲ │ ╱
  . ─ 2 ─ .   ← 上下左右4格中恰好2个灯
    ╱ │ ╲
  .   .   .   ← 对角4格不受约束
```

## 四、数据结构设计

### 核心类型定义

```typescript
// 格子类型
type CellType = 'white' | 'black' | 'black-0' | 'black-1' | 'black-2' | 'black-3' | 'black-4';

// 格子状态
interface Cell {
  type: CellType;           // 原始类型
  bulb: boolean;            // 是否有灯泡
  marked: boolean;          // 是否被标记(×)
  illuminated: boolean;     // 是否被照亮
  hasError: boolean;        // 是否有错误
}

// 游戏状态
interface GameState {
  grid: Cell[][];           // 当前盘面
  size: number;             // 边长
  difficulty: number;       // 难度等级 1-5
  status: 'playing' | 'won' | 'idle';
  history: Cell[][][];      // 撤销栈
  historyIndex: number;     // 当前历史位置
  startTime: number | null; // 计时开始
}

// 难度配置
interface DifficultyConfig {
  blackRatio: [number, number];   // 黑格比例范围
  clueDensity: [number, number];  // 数字提示密度
  minBacktrackDepth: number;      // 最小回溯深度
}
```

### 难度映射表

| 等级 | 名称 | 黑格比例 | 数字密度 | 回溯深度 |
|-----|------|---------|---------|---------|
| 1 | 入门 | 15-20% | 60-80% | 0 |
| 2 | 简单 | 20-25% | 40-60% | 1-2 |
| 3 | 中等 | 25-30% | 25-40% | 2-3 |
| 4 | 困难 | 30-35% | 15-25% | 3-5 |
| 5 | 专家 | 35-40% | 5-15% | 5+ |

## 五、谜题生成算法

### 生成流程

```
1. 选择模板
   ├── 根据边长和难度选择合适的对称模板结构
   └── 模板定义黑格的大致位置模式(中心对称/轴对称/分散)

2. 逆向生成解
   ├── 在白格中随机放置灯泡候选位置
   ├── 使用求解器验证是否能照亮所有白格
   └── 确保灯泡互不照射 → 得到有效解

3. 推导黑格数字
   ├── 对每个黑格，统计相邻灯泡数量
   └── 根据难度决定是否显示数字(困难=隐藏更多)

4. 约束精简
   ├── 移除多余的数字提示
   ├── 验证移除后仍有唯一解
   └── 重复直到保留最少必要提示

5. 难度校验
   ├── 用求解器模拟人类解题路径
   ├── 统计需要的推理类型和回溯次数
   └── 若不符目标难度，重新生成
```

### 模板示例

**7x7 对称模板**:
```
. . # . # . .
. . . . . . .
# . . . . . #
. . . # . . .
# . . . . . #
. . . . . . .
. . # . # . .
```

### 唯一解保证

生成后用求解器验证，若多解或无解则重新生成。

```

├─────────────────────────────────────┤

```

### 交互流程

**1. 初始状态**
- 显示下拉菜单和生成按钮
- 游戏区显示占位提示

**2. 用户选择并点击"生成新挑战"**
- 前端显示加载动画
- 调用生成算法（可能需要重试保证唯一解）
- 渲染棋盘，计时器开始

**3. 游戏交互**
- 点击空白白格：放置灯泡 + 区域点亮
- 点击有灯泡的格：熄灭 + 标记❌
- 点击有标记的格：清除标记
- 实时检测错误并红框标记
- 实时检测胜利条件

**4. 按钮功能**
- 提示：高亮可放置灯的格子 + 显示推理原因
- 撤销：回退上一步操作
- 重做：恢复已撤销的操作
- 重置：清空所有灯泡和标记，重新开始当前关卡

**5. 胜利**
- 显示祝贺弹窗
- 展示用时
- 可生成新挑战

### 下拉选项

**棋盘大小**: 5×5, 7×7, 10×10, 15×15, 20×20, 25×25, 自定义

**难度**: 入门、简单、中等、困难、专家

**自定义输入范围校验**: 最小5，最大25

## 八、错误检测规则

### 错误类型

| 错误类型 | 检测条件 | 红框标记 |
|---------|---------|---------|
| 数字超限 | 某数字周围灯数量 > 数字 | 当前格 + 该数字黑格 |
| 数字不足 | 某数字周围已无白格但灯数量 < 数字 | 该数字黑格 + 相关已放灯 |
| 灯照灯 | 灯泡被另一个灯照亮 | 互相照射的所有灯 |

### 实时检测流程

```
用户放置灯泡
    │
    ▼
检测该灯是否被其他灯照亮 → 是 → 红框标记冲突灯
    │
    否
    ▼
检测相邻数字黑格是否超限 → 是 → 红框标记当前格 + 黑格
    │
    否
    ▼
正常显示（黄高亮照亮区域）
```

## 九、求解器与提示功能

### 求解策略

按复杂度排序：
1. **满数推理**: 数字4周围必全是灯，角上2必全是灯
2. **差一推理**: 数字3周围有3个白格，则全是灯
3. **唯一照亮**: 某白格只能被一个位置照亮，该位置必是灯
4. **排除推理**: 放灯会导致冲突的位置必不能放灯
5. **假设验证**: 尝试放置，验证是否导致矛盾

### 求解器返回

```typescript
interface SolveResult {
  solvable: boolean;      // 是否可解
  unique: boolean;        // 是否唯一解
  solution: Set<string>;  // 解(灯泡位置集合)
  steps: ReasoningStep[]; // 推理步骤(用于提示)
}
```

### 提示功能

- 只提示灯的位置（绿框闪烁）
- 显示推理原因："该位置是唯一能照亮(行3,列5)的格子"
- 不提示标记操作
